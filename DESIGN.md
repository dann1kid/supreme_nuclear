# Supreme Nuclear — дизайн-документ

**Версия:** 0.4 (фабрики с очередями, поведение вне связи, парковка явным списком) · **Дата:** 2026-10-24
**Проект:** RTS-мод для Nuclear Option в духе Supreme Commander.
**Статус:** решения зафиксированы по итогам разведки (см. Реестр технических референсов в конце).

---

## 1. Видение

Оперативная RTS на больших (100×100+ км) симметричных картах с реалистичным вооружением Nuclear Option (BVR-ракеты, мощная ПВО, артиллерия) + уникальный гибрид: командир может лично летать. Темп — оперативный реализм, без ускорения времени. Драки длятся долго — это норма и часть геймплея.

Уникальность против SupCom:
- реальная аэродинамика и вооружение вместо «самолётов на 100 м»;
- личное участие: вселение в любой свой борт;
- 100×100 км против 20×20 у «больших» карт SupCom.

## 2. Зафиксированные решения

### 2.1 Командир = командирский борт игрока («летающий ACU»)
- Интерфейс командования — стратегический слой (оверлей + карта), **не** привязан к кабине.
- Борт — это: (а) юнит-условие победы, (б) узел связи (приказы в радиусе / через ретрансляторы), (в) опциональное личное средство: вселение в кабину в любой момент; без игрока летит сам (маршрут/орбита).
- **EMCON (радиомолчание):** борт глушит РЛС и связь — невидим для пеленга, но слеп и не командует. Симметричный риск.
- **Смерть командира = детонация БЧ** (нативные тактические/стратегические боеголовки) + конец матча.
- Посадка на свой аэродром = ремонт и окно уязвимости.

### 2.2 Экономика (v0.2, детализировано)

**Два ресурса, потоковая семантика (инвариант SupCom #1):**
- **Промресурс («масса»)** — добывается месторождениями (аналог мексов). Апгрейд T1→T2→T3 на самом здании.
- **Энергия** — генераторы (T1/T2/…). Потребляют: заводы (производство юнитов), радары, ПВО, стройка, апгрейды.
- Дефицит = пропорциональное замедление (производство/стройка едут со скоростью min(1, доступно/требуется)); перелив = копится в хранилище. Экранная панель «доход/расход/баланс» — обязательный элемент UI.
- Технически: поток считается mod-side; там, где игра требует `factionFunds`, — периодическая синхронизация эквивалентом (цены всё равно переписываем через `UnitDefinition.value`).
- Позже (не MVP): **топливо/боеприпасы как физическая логистика** — энергия+масса конвертируются в топливо/БО на базах, дальше грузовиками/вертолётами снабжения до аэродромов (паттерн GC supply proven). Это третий слой, дающий оперативную глубину, но не блокирует ядро.

**Экспансионный доход (инвариант SupCom #2):**
- Месторождения фиксированы генератором карт: чокпоинты, центр (жирные). Отдельный тип — **энергетические споты** (аналог гидрокарбонатных): дешёвая станция только на месте спота, ~×5 к эффективности обычного генератора; бонус, а не требование.
- Стартовый набор ресурсов слота = слайдер темпа матча (меньше стартовых мексов/запасов → медленнее и «армейнее» игра — подтверждено наблюдениями по SupCom).
- **Салваж обломков** — возврат массы с полей боёв (нативные wrecks; инженер подъезжает — собирает).

**Автономные командные машины (аналог SACU/«студентов»):**
- Тяжёлый дорогой юнит T3-стадии: инженер-боец. Пассивно **генерит массу+энергию** (как командирский борт), **строит T3-здания** (и эксперименталы, когда появятся), ассистит стройки.
- Пресеты при постройке (бой/инженерия/ресурс — как пресеты SACU).
- Синергия с принципом «стройка где угодно»: одиночная АКМ может тайно строить передовую базу в тылу врага.

**Принцип «без жёстких ролей»:** роли (авиация/наземка/флот/экономика) диктуются только стартовой позицией и стартовыми ресурсами слота. Любой игрок, выйдя в безопасное плато развития, может построить любую ветвь победы. Никаких залочек «этот слот не может строить флот».

**Тайминги (целевые, для среднего игрока; числа — плейсхолдеры до полигона):**

| Стадия | Цель (1v1 / 4v4) | Аналог SupCom |
|---|---|---|
| Первые стычки | 3–5 мин | T1 агрессия |
| T2 (MBT, дальняя ПВО, вертолёты, артиллерия) | 8–10 мин | T2 ~8 мин |
| T3 (стелс-бомберы, флот, тяжёлый танковый кулак) | 15–18 мин (растянуть из-за времени полёта) | T3 ~10 мин на Dual Gap |
| Первая стратегическая БЧ | 20–25 мин (при чистой экономике — 18) | нуклы ~15 мин у экономиста 1500 |
| Противоракетная готовность | к моменту первой БЧ у врага | ПРО к 15 мин |

Крутилки темпа: стартовые запасы, доход мексов по тирам, стоимость апгрейда T2/T3, скорость стройки БЧ-завода, порог эскалации по ущербу.

**Роли слотов на шаблонах карт (аналог позиций Dual Gap):**
- **Аэродромный слот** — усиленный стартовый аэродром + авиационные резервы, меньше мексов (покупает эффект дороже, но летает чаще).
- **Наземные слоты (1–2)** — больше мексов, вариативные расходы: тактические ракеты, мобильные РСЗО, стационарная артиллерия, ПВО-бункеры на линии соприкосновения, танковые массы.
- **Тыловой-экономист** — максимум мексов в тылу, отвечает за T3 и противоядерную защиту команды.
- **Морская позиция** (шаблоны типа Setons) — флот: нативно влиятелен (HP, мультиролевые башни: ПВО + противолодочные + дальнобойные), T2-стадия растянута, корабли = квази-эксперименталы по весу.
- Асимметрия стартовых ресурсов между слотами задаётся шаблоном карты (как в SupCom), а не фракцией.

**Стройка и «вливание» (инженер-ассист — как в SupCom):**
- Любая задача (юнит/здание/апгрейд/БЧ) — это `BuildTask` с полем `drainRate`; несколько инженеров на одной задаче суммируют свой `assistRate` → стройка едет быстрее, но вычитает больше потока. Это и есть «вливание массы/энергии через инженеров и само здание».

### 2.3 Строительство
- **Стройка где угодно** (инженеры, как в SupCom), БЕЗ радиуса базы (анти-паттерн C&C из Ground Control — отвергнут).
- Секретные передовые базы в тылу врага — поддерживаемая фича (следствие: разведка имеет ценность, скрытность строительства — механика).
- Аэродромы — обычные здания (логистика: ёмкость авиации, реарм/ремонт, взлётные полосы), не «владение территорией». Строятся/захватываются как любые структуры.
- **Архитектурный принцип:** вся стройка — API сериализуемых задач (`BuildTask` и др.), общий для UI игрока, AI-командира, мультиплеера и сейвов. AI не может «не уметь строить».

### 2.3-1 Механика стройки SupCom (целевая модель, объяснена игроком 2026-10-26)

- **Инженерный модуль** — «апгрейд», который у инженера выдаётся при создании: им он
  **вливает** ресурсы в стройку (не «строит время», а прокачивает массу/энергию).
- **Shift+ЛКМ** расставляет очередь точек постройки — инженер итеративно использует их
  как вейпоинты: подъехал → залил до конца → поехал к следующей.
- **Несколько инженеров** на одной задаче вливают пропорционально больше — стройка быстрее.
- **Тир инженера** расширяет список доступных к постройке объектов; у каждого инженера есть
  **фактор строй-мощности** (у командира SupCom по умолчанию 10): инженерный модуль повышает
  и тир, и фактор; фактор определяет скорость вливания ресурсов (по формуле экономики).
- Реализовано в v1 (0.35.1): shift-серия площадок, цепочка задач как вейпоинты,
  пропорциональное ускорение от N инженеров (у всех фактор 1). Тиры/фактор/модули —
  вместе с модовыми определениями инженеров и потоковой экономикой (2.2, этап B+).
- **НЕДОСТРОЙ (v0.44.0, философия игрока)**: сорванная инженером стройка НЕ отменяется
  и БЕЗ возврата денег остаётся площадкой с уплаченным прогрессом — её подхватывают
  другие инженеры (ПКМ/shift+ПКМ по недострою выделенными инженерами = достройка).
  Сценарий: T3 инженер ставит дорогие здания и срывается; пачка T1/T2 прокликивает
  недострои и достраивает. Полное удаление площадки — только кликом по плитке очереди.
- **ПКМ ПО ПРИЗРАКУ = ПРИКАЗ СТРОЙКИ (v0.95)**: клик инженерами по силуэту призрака
  (или любой точке полосы недостроенной ВПП) — адресная достройка, не движение к точке
  земли; без Shift — новая очередь (только эта задача), с Shift — дописать в очередь.
  Подход к площадке — КОЛЬЦОМ ВНЕ ГАБАРИТА: строители расходятся веером по азимутам
  вокруг призрака и останавливаются у границы футпринта (не въезжают внутрь).
- **ИНЖЕНЕРНЫЙ ПАТРУЛЬ (v0.95, канон SupCom)**: патруль — цикл точек (доступен авиации
  и наземке/флоту; ПКМ по вейпоинту маршрута замыкает его в цикл). Инженер в патруле
  сам подхватывает близлежащий недострой своей фракции (радиус — настройка, 0 = выкл),
  достраивает и возвращается на маршрут; явный приказ игрока отменяет ассист без
  возврата патруля.
- **Приказы = вейпоинты намерения (v0.44.0)**: у КАЖДОЙ единицы своя очередь
  (движение/стройка/взлёт/посадка/атака — одна цепочка на юнита); shift+ПКМ дописывает
  в очередь КАЖДОМУ выделенному свою точку; добавление юнита в группу посреди
  прокликивания — последующие вейпоинты получают только текущие выделенные.
  **Shift = режим добавления** вообще: дописывание в очередь И добавление в группу
  (shift+клик по юниту / shift+рамка).

### 2.3a Производство: фабрики с очередями (дефолт v0.4)
- Покупки «по клику за деньги» (паттерн GC-депо) — только костыль для самого первого вертикального среза. Целевая модель — **фабрики с очередями**: заказы стоят в очереди, фабрика непрерывно наливает массу+энергию (`drainRate`), юнит выходит по мере «наполнения». Дефицит потока = пропорциональное замедление всех очередей.
- Приоритеты очереди и точка сбора (rally point) — обязательны. Инженер-ассист ускоряет и производство (суммарный `assistRate`).
- **Групповое управление фабриками** (v0.100, канон SupCom «фабрики управляемы пачкой»): при мультивыделении фабрик (любых типов — депо/ангар/верфь/аэродром) кнопки Пауза/Цикл действуют на ВСЕ выделенные (унификация состояния: все на паузу ↔ все сняты; подсветка — «все в состоянии»), ПКМ задаёт общий ралли-маршрут сразу всем (Shift — дописать точку; одинаковые маршруты рисуются одной лентой). Точки ралли несут groupId клика (v0.105): спущенная пачка получает ГРУППОВЫЕ вейпоинты — общий маркер/драг/удаление, как у приказов юнитам напрямую; Shift-режим видимости показывает ралли и невыделенных фабрик приглушённо. Ралли ангара: свой маршрут; нет своего — наследуется ралли аэродрома (выделение аэропорта задаёт общий маршрут всем своим ангарам); борт получает план Transit сразу после спавна (выкат/взлёт — нативно).
- Тиры: апгрейд фабрики на месте (T1→T2→T3) или постройка новой — обе опции, дефолт — апгрейд на месте.
- Авиация производится на аэродромах. **Ангар = индивидуальная фабрия с своей очередью** (РЕШЕНО v0.88; эволюция: v0.67–v0.87 — общая очередь аэродрома с параллельными слотами): у каждого ангара свой каталог (`availableAircraft` префаба) и один поток оплаты; параллельность = число ангаров с заказами. Основной способ управления — ГРУППА: выделил пачку ангаров (даблклик по ангару = все ангары аэродрома) → клик по плитке = +1 каждому умеющему строить. Причины решения: паттерн SupCom (фабрики управляемы пачкой) + физика игры — обломки разбитых ангаров блокируют выезды соседей, компактный грид = связанная цель, рассредоточение = живучесть (скилл раскладки). Панель аэропорта (вышка/умное распределение `EnqueueAirDistributed`) остаётся агрегатом. Флот — на верфи (РЕШЕНО v0.92, от «naval dock паттерна GC» отказались): верфь = ПЛАТФОРМА НА ВОДЕ в духе SupCom — инженер ставит её где хочет (глубина ≥ DockMinDepthM), инженеры-«пловцы» доплывают и строят (костыль плавучести Jackknife, юзер 2026-10-27: «позже эти гиммики заменим»); корпус = здание-депо на меш-платформе (пирса в контенте нет, зонд v0.91.1), производит ФЛОТ третьей фабрикой ProductionTasks (очередь/поток/пауза/цикл/ралли), спуск корабля — кольцами в ближайшую валидную воду (глубина/габарит/занятость), занятая вода не сжигает позицию; тиры каталога — терцилем по цене (T1 катера/десантные, T2 корвет/фрегат/док, T3 эсминец/LHA/CV).
- **Ёмкость аэродрома наращивается стройкой** (v0.78.0, переработано v0.80–0.81): здания-ангары из каталога игры инженер строит рядом со своим аэродромом (радиус `HangarAttachRadiusM`); место не обязано быть на карте-бетоне — мод дорисовывает и граф рулёжки, и ПОВЕРХНОСТЬ под неё (плиты-коллайдеры: для шасси игры любой коллайдер с материалом ≠ террейну — тармак, шасси не вязнет); РЕШЕНО (v0.100): подключение ангаров — через общий КОЛЛЕКТОР — одна рулёжная магистраль параллельно ВПП на стороне ангаров, съезд на полосу одной S-кривой у торца, ангары — короткими коннекторами к её середине (паттерн нативного аэродрома; до v0.100 каждый ангар вёл собственную дорожку к слиянию — подходы стагер-грида пересекались); направление выката задаётся удержанием ЛКМ при постановке. Привязка нативная (`Spawner.SpawnBuilding(..., airbase)`), новый ангар = ещё один слот мультифабрики. Источник спавна остаётся нативным (см. следующий пункт).
- **Источник спавна авиации — ТОЛЬКО родные аэродромы игры** (`Airbase.TrySpawnAircraft`/ангары): их ВПП/такси/посадка работают штатно. Самодельные ангары-спавнеры (как у GC) не используем — по опыту беты ставятся криво и сломаны. Передовые площадки для VTOL — позже через нативный `SpawnCustomAirbase` с VerticalLandingPoints (v0.9 разведка это подтвердила).
- **ВПП строится инженером** (v0.87.0, этап 3): драг «торец → торец» (900–4000 м, реверсивная взлёт/посадка), по готовности — нативный `SpawnCustomAirbase`: новый ЗАХВАТЫВАЕМЫЙ аэродром со своей очередью и своим гридом ангаров. Паттерн «несколько фабрик» SupCom реализован на уровне «полоса + её ангары» (решение 2026-10-27: отдельные очереди ПО-АНГАРАМ отвергнуты — микрошум; больше полос = больше фабрик), специализация «тяжёлые ближе к полосе, мелкие дальше со стеком на подъезде» рождается сама из типов ангаров, длины рулёжек и нативной очереди взлёта.

### 2.3b Поведение вне радиуса связи (дефолт v0.4)
- Юнит, потерявший связь (вышел из радиуса командира/ретрансляторов), **доигрывает текущий приказ**, затем переходит в автономную оборону (держит позицию, отвечает огнём).
- Циклические приказы (патруль/маршрут) продолжают выполняться до последнего.
- UI обязан явно показывать «нет связи» на юните/группе.

### 2.4 Карты
- **Большие симметричные сгенерированные** карты. Требования: ≥50% манёвренных равнин (танковые бои, контрудары), горы по краям и редкими хребтами (авиационная игра), чокпоинты (река/ущелья), центральные богатые месторождения.
- Шаблоны: Dual Gap (базы + сухопутный мост), Seton's Clutch (континенты вокруг центрального моря), зеркальная симметрия — генерируем половину, отражаем.
- **Две культуры карт — обе в пуле:** (а) фиксированные шаблоны/сид для соревновательных быстрых билдов («знатоки одной карты») и (б) рандом-генерация с хаотично раскиданными мексами и медленными стартами (супер-адаптивные игроки). Генератор один, различается раскадровка депозитов.
- Путь: оффлайн-генератор AssetBundle (пайплайн NOMapLoader доказан Swiss Alps) → позже рантайм-генерация (все примитивы подтверждены: меши, traversability-текстура, RoadNetwork, `SpawnCustomAirbase`).
- Стоковые карты («реальные места», асимметрия) — не для RTS, не используем.

### 2.5 Боевой баланс
- ПВО мощная — норма. Ядро контр-игры — **SEAD-цикл**: разведка → помехи → противорадиолокационные ракеты → удар. Артиллерия бьёт статику (area-fire по точке карты — доказано GC).
- Треугольник: авиация ↔ ПВО ↔ артиллерия/наземка. Точная математика — открытый вопрос.
- Авиация — инструмент разведки/удара, не DPS-бол (BVR вместо dogfight-бол).

### 2.6 Стратегические БЧ: органический баланс вместо гейтов (v0.3)
**Отказ от «эскалации по ущербу» как разрешения** — механика хороша для ванильного Nuclear Option, но в RTS-режиме заменяется органической контригрой в духе SupCom:
- **БЧ-завод строится где угодно** (никаких уникальных месторождений — иначе перманентный снос добытчика превращает стратегическое оружие в мёртвую механику). Дорогой, энергожоркий, **заметный на разведке** (крупная сигнатура: раз увиден — виден всем).
- **ПРО строится быстрее и дешевле первой БЧ** — как в SupCom: засёк ядерное ядро → ушёл в экономику/ПРО и успел. Цикл «разведка → реакция» заменяет разрешающую систему.
- **Риск раннего выхода** — плато уязвимости: пока строишь БЧ-завод, армия тоньше; противник это видит (мало техники на разведке) и наказывает штурмовиками/танковым рейдом. Самобаланс через разведку, не через скрипт.
- Нативные гейты эскалации в нашем режиме **отключаются** (патчи `MissionManager.AllowTactical/AllowStrategic` — цели уже доказаны GC). Нативная эскалация остаётся для ванильных режимов игры.
- Производство = потоковая стройка с инженер-ассистом (`BuildTask.drainRate`), наполняет **нативный** warhead stockpile (`FactionHQ.AddWarheadStockpile`) — носители, пусковые и применение берутся из игры бесплатно.
- Тактические БЧ — та же система, дешевле/быстрее, меньший масштаб.
- Урановые месторождения **исключены из v1** (возможный возврат позже — как опциональный ускоритель БЧ-завода ×1.5, не как требование).

### 2.7 Победа
- **Гибрид:** дуэль командиров (убей борт) + система objectives (нативная) для PvE-миссий; задел на кампанию.

### 2.8 Мультиплеер
- Режим **«командир + асы»** (один командует, остальные летают его бортами) — да, целевой. Не MVP.
- **Респаун асов (дефолт v0.4):** летающие игроки возрождаются на аэродроме своей фракции (нативно), смерть командира = конец матча. Ас, чей борт сбили, возвращается на следующем свободном борта из резерва.
- **Передача ресурсов союзникам (дефолт v0.4):** отправка массы/энергии союзнику кнопкой (для командной игры «фид экономиста»). Передача юнитов — паркинг.
- MVP-сингл: игрок против AI-командира.

### 2.9 Парковка (явный список отложенного)
- **Эксперименталы** — возможно модовые юниты позже.
- **Энергощиты** (ты про Т2-щиты в бункерах) — технически возможны (патч `UnitPart.TakeDamage` доказан GC), но новая механика; решение после первых полигональных стычек с ПВО.
- **Масс-фабрикаторы** (конвертация энергия→масса поздней игры) — нужен только если карты упираются в исчерпание мексов; ввести при необходимости.
- **Погода/время суток как геймплей** (ночные операции, влияние ветра на авиацию) — нативная среда игры это умеет; геймплейное использование — после ядра.
- **Передача юнитов союзникам, зрители, рейтинг** — MP-инфраструктура, далеко.

### 2.10 Нижняя панель командования — эталон SupCom FA (спека от 2026-10-26, со скриншотов игрока)

Эталон для нашей нижней панели. Записан до реализации; дорабатывается под NO.
Реализация — этап B (вместе с Task-API/фабриками). Раскладка панелей экрана — ARCHITECTURE §8.

**Три вкладки** (иконки, вертикальный селектор сбоку):
1. **Гаечный ключ — стройка/производство.**
   - Две строки. **Верхняя — строка заказа**, визуально подразделена: «апгрейд на тир выше» / «юниты».
   - Над ней 5 иконок переключения пула заказа: **тиры I, II, III, экспериментальные (круг), шаблоны (2 квадрата)**.
     Кнопки тира показывают в строке заказа юниты выбранного тира.
   - **Шаблоны**: запомнить текущую очередь кнопкой «шаблон» сбоку; применение шаблона заказывает
     пачку юнитов без ручного набора (автоматизация). Шаблоны работают и для постройки зданий,
     не только очередей юнитов.
   - Кнопки у строк: **«цикл»** (зацикливание очереди — бесконечное производство) и
     **«пауза/воспроизведение»** производства. Активное состояние — яркая подсветка.
   - По **8 кнопок прокрутки на строку**: листать иконки влево/вправо по одной и до конца в обе стороны.
2. **Список юнитов.**
   - **Верхняя строка — выделенные объекты** (в SupCom: shift+клик или обводка; здания НЕ обводятся
     рамкой, чтобы не мешали — добавляются в выделение только прокликиванием, накапливаясь в строке).
   - Элементы строки разделены **визуальными промежутками по категориям**: юниты / инженеры
     (занятые и свободные отдельно) / боевые / здания / функциональные объекты / заводы.
   - **Нижняя строка — строка заказа инженеров**, если в выделение попали заводы.
   - При **множественном выборе заводов** очереди в нижней строке НЕ показываются
     (в каждом заводе может быть своя очередь).
3. **Апгрейды командира и SACU** — для NO пока не актуальна (задел под командирский борт/АКМ).

**Адаптация под NO (открытые пункты к этапу B):**
- Вместо двух ресурсов mass/energy — пока деньги (`factionFunds`); панель потока — этап C.
- Авиация производится на аэродромах (ёмкость ангаров вместо слотов очереди).
- «Экспериментальные» — пусто до появления эксперименталов (паркинг-лист 2.9).
- Шаблоны v1 — именованные наборы заказов; сохранение между матчами — после сейвов.
- Прокрутка строк и «цикл/пауза» переносятся как есть; «цикл» требует фабрик с очередями (Task-API).
- **Плитки читаемости (решение 2026-10-26, реализовано v0.60.0)**: у каждой плитки
  каталога/очереди/ростера — короткая подпись юнита внизу (бортовой `code` из игры,
  иначе первое слово имени) и бейдж ТИПА объекта в левом-верхнем углу с цветом по
  классу. Авиация — индивидуальный силуэт `mapIcon` (тот же, что на макрокамере и в
  нативном меню выбора борта), роль выводится из роли armed: И/У/М (слабый боец —
  ТР-транспорт или РЛС-ДРЛО). Наземка — бейдж из типа техники: ТНК/ББМ/ЛБМ/АРТ/ЗУ/
  ПЗРК/ЗРК/РЛС/ГРЗ/БНП (цвета: броня зелёная, артиллерия оранжевая, ПВО фиолетовая).
  Право-верх плитки: в каталоге — цена, в очереди — ×N стака.
- **Клики по стакам очереди фабрики (решение 2026-10-26, v0.60.0)**: ЛКМ по плитке
  стака добавляет единицу В ТОТ ЖЕ стак (не в конец очереди), ПКМ снимает единицу
  с конца стака с возвратом уплаченного; Shift — ±5. Головная позиция (в работе)
  снимается последней.
- **Hover-инфоокно плиток (решение 2026-10-26, v0.60.0; переработано 2026-10-27,
  v0.86.0 в панельную схему по плейтесту — карточка у курсора убрана; v0.87.0 —
  переключение МГНОВЕННО, без задержки 0.35 с)**: наведение
  на плитку каталога/очереди/ростера переключает ЛЕВУЮ панель свойств
  (заголовок «ЗАКУПКА») на карточку ОПРЕДЕЛЕНИЯ — имя, класс/роль · цена · оценка
  времени (фабрика ~ProductionSecondsPerItem, стройка ~BuildSecondsPerBuilder на
  инженера), строка ТТХ (обзор/скорость/броня/экипаж), вооружение дефолтной нагрузки
  с префаба (домен-тег АА/АЗ/У/ПР/РЕБ/Я + имя ×боезапас, до 8 строк, дальше
  «+ ещё N типов»); описание — во ВТОРОМ окне «ОПИСАНИЕ» под панелью (перенос до
  7 строк, длиннее — «…», высота окна под контент). Уход курсора возвращает панель
  к выделению. Отключается настройкой `UI.UiTooltips`.
- **Лодауты заказов авиации — колесом над плиткой каталога (решение 2026-10-27,
  v0.88)**: у авиации с именованными пресетами (`StandardLoadouts`, без disabled)
  колесо мыши над плиткой каталога циклит выбор: «Стандарт» (пустой лодаут — игра
  берёт свой дефолт, поведение до v0.88) → пресеты по кругу. Выбор ЛИПКИЙ по типу
  борта (как профиль высоты); позиция очереди запоминает лодаут и топливо
  (FuelRatio пресета) в момент заказа — смена выбора не перекрашивает очередь;

  пилонов сета); плитка каталога помечает отступление суффиксом «·ЛN». Легальность
  пресета — по тем же проверкам, что у AI игры (`AllowedByHQ` — ядерные квоты,
  `WeaponChecker` — наличие пилонов на аэродроме): недоступный подписан в карточке

  РЕДАКТОР ОСНАЩЕНИЕ (решение 2026-10-27, v0.90): СКМ по плитке каталога

### 2.11 Приказы атаки и целеуказание (решения 2026-10-26)

Сформулировано по итогам разбора нативной механики боевого AI (см. §5): в NO цель выбирает
сам `CombatAI.ChooseHQTarget` из трекинг-базы фракции, у мода нет прямого API «атакуй X».

- **Целеуказание — только через даталинк фракции** (нативная `FactionHQ.trackingDatabase`:
  контакты, держимые сенсорами, с точностью позиции; это же используют боевой AI и ГСН
  ARH-ракет). Без трека огонь не открывается — КРОМЕ вооружения, работающего по точке:
  бомбы, баллистика, артиллерия бьют area-fire по точке карты без даталинка.
- **ПКМ по конкретной цели = гарантированный огонь доступными средствами.** Борт пиннится
  на указанную цель и применяет подходящее вооружение: нет ракет ВВ — не лезет в ракетный
  догфайт; есть пушка и враг рядом — пушечный заход; доступно только ВП — атакует только
  наземные цели. Наземка — та же логика: подход на дальность своего вооружения, огонь
  нативными турелями.
- **Групповая атака наземки/флота — ПОЛУКРУГОМ (v0.77.0)**: каждому атакующему клик
  назначает свой азимут-сектор вокруг цели (веер с шагом FormationSpacing по дуге радиуса
  подхода юнита, порядок — по азимутам, маршруты не пересекаются). Каждый держит свой
  сектор, пока цель двигается; дальнобойные встают внешним кольцом по своей дальности,
  ближнее — внутренним; боеприпасы кончились → юнит сам подтягивается на дальность
  оставшегося вооружения. Одиночный приказ и цели, дозревающие из смешанной очереди,
  подходят по живому азимуту юнит→цель. Оверкилл-перераспределение отклонено: снаряды и
  ракеты сбиваются/промахиваются — честной механики «цель уже мертва» для перехватываемых
  атак нет; распределение по целям — «Атака веером» (R).
- **Атака по вектору (A / T-клик по земле) = конусная атака по всем целям в секторе
  доступными средствами**, с тем же фильтром по классам вооружения (ВП без ВВ не гоняется
  за самолётами и наоборот). **Распределение целей группы ЛА (v0.99.0, патруль — тоже)**:
  нативный выбор ранжирует цели opportunity×(1+угроза)/дистанция — у плотной группы бортов
  скоры совпадают и вся пачка фокусит одну цель; мод ведёт реестр занятости (итоговые цели
  всех бортов) и борт УДЕРЖИВАЕТ свою цель, пока без него на ней меньше бортов, чем ёмкость
  ⌈N/M⌉ (N — наши борта с целями, M — чужие живые цели в конусе приказа); «лишний» борт
  переходит на лучшую по натив-скору недозанятую цель в конусе, недозанятых нет — остаётся
  в фокусе («насколько хватает ЛА в группе», излишек концентрируется, качелей нет — уходят
  только лишние). Явные цели (атака ПКМ/веер/залп) бронируются пиннингом и считаются
  занятыми; сходимость — 1–2 цикла оценки натива (5 с).
- **Наземка дерётся автоматически при движении** (нативный автоогонь турелей сохраняется).
  Attack-move наземки: движение → обнаружение цели → **остановка и огонь** → цель
  уничтожена → продолжение к точке вектора → при новом обнаружении повторить.
- **Авиация — вылеты, не перманентный приказ**: боеприпасы/топливо конечны; «сухой» борт
  или топливо ниже порога → RTB → перевооружение/заправка → повторный вылет, пока цель
  жива и приказ не отменён.
- **Распределение ракетного залпа по соседним целям — принимаем как есть** (нативный
  `CombatAI.LookForMissileTargets` размазывает залп по целям у точки пуска): жёсткий фокус
  одной цели гарантируется только пушечным/бомбовым оружием.
- Техническая основа — **реализовано v0.62.0 (2026-10-26)**: пиннинг цели — Postfix
  `AIPilotCombatModes.AssessHQTarget` (третий патч, реестр ARCHITECTURE §6) с подбором станции
  по `CombatAI.AnalyzeTarget` и даталинк-гейтом; Attack-сегмент — миссия вылета (подлёт по
  `GetKnownPosition`/якорю клика, зона боя = дальность вооружения × `AttackEngageFactor`);
  RTB при «сухих» станциях/топливе < `RtbFuelLevel` → нативная посадка → аэродромный сервис
  (`RpcRearm`+`Refuel`, интерим до логистики, вопрос §3-7) → повторный вылет; наземка —
  attack-move со stop-and-fire и атака цели подходом на дальность вооружения.
  **v0.63.0 (2026-10-26): вертолёты/тильтвинги** — те же приказы (патчи №4/№5 на
  `AIHeloCombatState`, вертолётная перегрузка автопилота, вертикальная посадка в цикле вылета);
  корабли покрыты общим путём наземки с v0.62.0.
- **Команда «на базу» (G) = возврат в РЕЗЕРВ ангара (v0.67.1, решение 2026-10-26)**:
  терминальный RTB — весь план борта заменяется на [Rtb к ближайшему подходящему своему
  аэродрому]; **v0.98: Shift+G — RTB дописывается в ХВОСТ очереди** (как прочие приказы,
  `EnqueueRtb`): борт отработает план и вернётся; когда очередь до RTB дойдёт, он
  останется единственным сегментом — терминальный (резерв). RTB в хвосте уже есть —
  повторный Shift+G ничего не добавляет. Дальше RTB дописывать можно — он становится
  физической посадкой-сервисом-взлётом (как авто-RTB), очередь продолжится.
  сел → сервис (20 с / деньги: полный боезапас и баки) → **деспавн в резерв
  ангара** (`AirbaseReserve`): невидимый инвентарь базы — не блокирует полосы/рулёжки,
  не тикает в симуляции. Самолёт на время сервиса паркуется (перехват на такси), вертолёт
  паркуется нативно. **Выкат** — плиткой «РЕЗ ×N» в панели аэродрома: бесплатно, нативный
  спавн из ангара (ёмкость ангаров проверяет игра); выкаченный борт таксует/взлетает и
  живёт обычной жизнью. Резерв привязан к базе и **теряется вместе с ней при захвате**;
  выкат — только со своего аэродрома. Авто-RTB вылета ([Rtb, Attack…]) — ФИЗИЧЕСКИЙ:
  посадка/сервис/взлёт без деспавна. Отложено: сервис-слоты на базу (пропускная
  способность обслуживания — фаза балансировки темпа операций). Вопрос ремонта — §3-10.

### 2.11a Режимы полёта, авто-защита и залп (решения 2026-10-26, v0.68.0)

- **Высота и скорость — свойства УЧАСТКА маршрута (сегмента), не точки**: режим на момент
  клика штампуется на участок; смена режима (Alt+1..4 / Shift+1..3) посреди Shift-серии
  режет новую ногу маршрута. Переключение при выделенных бортах применяется к головному
  участку немедленно (кроме RTB — домой летим крейсером на его высоте). Вертолётам
  доступна высота (AGL + огибание рельефа — вертолётный автопилот), скорость — нет
  (тротл считает hover-контур игры; осознанное ограничение, долг §12).
- **Профили высоты: 4** — Сверхнизко 75 м / Низко 150 м (оба с огибанием рельефа),
  Средне 800 м, Высоко 2500 м; числа — в Settings.
- **Скоростные режимы (самолёты): Полный 1.0 / Крейсер = бортовой cruiseThrottle /
  Эконом = настройка.** Эконом — для дальних перегонов/патрулей.
- **Авто-защита (РЭБ-авто) — три режима на борта, по умолчанию «Авто»**:
  «Авто» — при ракетном предупреждении руление отдаётся нативному уклонению (самолёты —
  манёвр увода + авто-ловушки; вертолёты — нотчинг + снижение + джаммер), после ухода
  угрозы план продолжается; «Ловушки» — маршрут держим, контрмеры по типу ГСН входящей
  ракеты с интервалом; «Выкл» — прорыв без реакции. Джаммер/чафф/ловушки выбирает
  нативный `ChooseCountermeasure` по типу ГСН — отдельных режимов РЭБ/EMCON не вводим.
  Ручной сброс — X/кнопка по выделению.
- **Залп (V) — намеренный запуск нативного распределения**: ПКМ по цели — залп-сегмент с
  явной целью; ПКМ по земле — залп по площади (при подлёте к якорю цели ищет даталинк);
  **Shift+ПКМ по целям дописывает цели в ОДИН залп** («разом по нескольким»). В зоне боя
  SalvoService пускает выбранные ракетные станции через нативный путь
  (`LookForMissileTargets` → `WeaponManager.Fire` → `SalvoFire`), расход на цель —
  `CalcAttacksNeeded`, потолок — настройка. Выбор станций — чипами панели (одиночный
  борт; по умолчанию все ракетные). Бомбы/пушки — залпом не пускаются (нативный бой;
  долг §12). После отстрела «сухой» борт — авто-RTB (физический) → перевооружение →
  продолжение плана.
- **Панель команд — контекстная (v0.68.0)**: состав кнопок перестраивается по типам
  войск в выделении (авиация — приказы + высота/скорость/защита/чипы станций; наземка —
  только применимые приказы); карточка растёт вверх, панель свойств поднимается за ней.
- **Атака веером (R, v0.70.0) — раздача группы по нескольким целям** (адаптация FAF
  Spread Attack): ПКМ по врагам в режиме накапливает список целей (маркеры-кресты с
  номерами, дедуп, живость), ПКМ по земле — выдать. Распределение `Util.AssignBalanced`:
  каждый атакующий — к БЛИЖАЙШЕЙ цели со свободной ёмкостью; атакующих не меньше целей —
  ёмкость N/M (+1 первым по порядку клика, ровная раздача без давки на ближней цели);
  атакующих меньше целей — ёмкость 1, каждый берёт ближайшую свободную (дальние клики
  остаются без атакующих). Авиация получает атаку-вылет (якорь — позиция
  цели), наземка/флот — преследование; инженеры не воюют. Пустой список при выдаче —
  деградация в атаку-движение. Веер не комбинируется с залпом (долг §12).
- **Disperse Move (Alt+Shift+R, v0.70.0) — распределение очереди вейпоинтов** (паритет
  FAF Disperse Move): по уже поставленной Shift-серией групповых вейпоинтов юнит i
  получает группу точек i mod G (G групп в остатке очереди, порядок клика = рост groupId),
  у каждого остаётся ОДНА точка — прямой вектор вместо общего маршрута; своей группы нет
  (индивидуальные вклинивания) — прямой вектор к последней оставшейся точке. Наземка/флот
  и авиация распределяются независимо; инженеры (общая очередь стройки) не участвуют
  (долг §12); точки сохраняют groupId — драг/удаление остаются групповыми.
- **Гейты вооружения (v0.71.0, решение от 2026-10-27) — вкл/выкл классов оружия по
  выделению**: пять классов (`Catalog.ClassOf` по `WeaponInfo`: «ЯД» ядерное, «Бомбы»
  bomb/glideBomb, «Пушки» gun, «Рак.ВВ» ракеты с воздушным доменом, «Рак.АС» прочие
  ракеты). Кнопки — полосой внизу командной карты, только классы, присутствующие в
  выделении; клик — тоггл всему выделению (цвет: зелёный — всем разрешён, красный —
  всем выключен, жёлтый — вперемешку). **Гейт главнее явных приказов** (решение
  игрока): выключенный класс не применяется НИКОГДА — ни автоогнём по пути, ни в
  атаке-движении, ни в ПКМ-атаке, ни в залпе V. Асы-люди не затрагиваются (ручной
  пуск идёт мимо гейта). Гейт переживает смену выделения и приказы, сбрасывается
  по смене сцены.
  **Правила по ТИПАМ и доменам целей (v0.106.0, запрос игрока 2026-10-28)**: вторая
  строка секции — чип на каждый тип вооружения выделения (distinct `WeaponInfo`,
  по убыванию полного боезапаса, кэп 6). ЛКМ циклит шесть состояний: без правил →
  только по наземным целям → только по воздушным → пуск только с наземных → пуск
  только с воздушных → выкл; колесо над чипом — туда-обратно (как лодауты); выбор
  дублируется Notice-ом. Домен цели: летящий борт (radarAlt > 1 м, эвристика самого
  CombatAI) и ракета в полёте — воздушный; техника/флот/постройки/паркованный борт —
  наземный. Платформенные состояния — макрос над per-unit правилами («пуск только
  с наземных» = авиации выделения тип запрещён, наземке свободен). Мотивация:
  универсальные по запуску/попаданию ракеты (AGM-48) жалко тратить по воздуху —
  «только по наземным» держит их для земли.
  **Принуждение (v0.106.0)**: главная линия — Harmony-префиксы `WeaponStation.Fire`
  и `WeaponStation.LaunchMount` — единый предохранитель ВСЕХ путей применения
  (турели; FireControl ПВО-батарей/кораблей/стратегических пусковых, который раньше
  обходил и гейты, и стойку; боевой AI авиации; наш залп; сетевые Cmd/Rpc-пуски);
  хост-only, ас-человек исключён (как нативный SafetyIsOn), блок — до оригинала
  (боезапас не тратится). Дополнительно: турель не берёт цель, если ни одна её
  станция не проходит правила против КАНДИДАТА (проверка по кандидату, а не по
  текущей станции — скип по текущей замораживал нативный выбор станции и глушил
  разрешённое оружие смешанной турели, пушка+ракеты); боевой AI авиации перевыбирает
  разрешённую станцию или снимает цель. Hold-fire ортогонален и гасит всё сразу —
  теперь ЧЕСТНО: и FireControl, и залп V, и боевые вылеты (борт в стойке не вступает
  в бой, цель снимается); чипы станций залпа — выбор «чем палить залпом», уважают
  гейт и правило типа.
- **Сопровождение/ассист союзного юнита (v0.97.0, запрос игрока 2026-10-27)** —
  вейпоинт, ПРИВЯЗАННЫЙ к юниту: **ПКМ по союзному мобильному юниту** (в дефолтном
  режиме «Движение») выделяет его целью сопровождения.
  - **Боевые наземка/флот** следуют за целью СВОИМ сектором (группа распределяется
    веером азимутов вокруг цели, как полукруг групповой атаки); догнав цель —
    защищают её семантикой атаки-движения (stop-and-fire; флот дерётся на ходу),
    не отставая из-за боя на полкарты. **Движение — плавно, по следу цели** (v0.98):
    якорь эскорта скользит по Catmull-Rom-сплайну breadcrumbs её траектории
    (шаг/длина следа — настройки) на дистанции позади, сектор веера переводится в
    «продольно позади + сбоку от маршрута» — колонна повторяет путь цели без
    рывков между перевыдачами точек; цель стоит дольше пары секунд — охрана
    собирается кольцом вокруг неё, отставший эскорт догоняет прямым вектором.
  - **Инженеры** сопровождают цель и **вливаются в её стройки** (SupCom assist):
    цель начала строить — инженер присоединяется к её задаче (ускорение = N
    инженеров), достроил — вернулся к сопровождению; чужие недострои не трогаются
    (ассист адресный, в отличие от патруль-ассиста). Явный приказ снимает ассист
    без возврата.
  - **Авиация** сопровождает полётом: держится у цели (сектор веера группы, вблизи —
    орбита), враг в дальности вооружения — нативный бой, после боя следование
    продолжается; Shift+ПКМ дописывает эскорт в план борта (план-модель умеет
    очереди бесплатно). Боеприпасы/топливо — как у вылета (сухой борт — RTB-цикл).
  - Снятие: S/новый приказ — как обычно; Ctrl+Shift+ПКМ по цели связи снимает
    сопровождение у всех её эскортировщиков сразу. Наземке сопровождение в очередь
    НЕ ставится (цепочка без точек; осознанное ограничение, ARCHITECTURE §12-36).
  - Цель — любой свой мобильный юнит (наземка/флот/авиация); здания статичны —
    сопровождать нечего (ассист производства фабрик — с потоковой экономикой §2.2).
  Дистанция следования и смещение авиации — настройки (`EscortStandoffM`,
  `EscortAirDistM`).

### 2.11b Тумблеры аэродрома «доступен для посадки / взлёта» (решение 2026-10-28, v0.101.0)

- **Разграничение ВПП по функционалу (запрос игрока)**: у аэродрома два независимых
  тумблера — «Без посадки» / «Без взлёта» (кнопки контекстной колонки панели,
  подсветка = закрыто; под ромбом своего аэродрома — метки «посадка закрыта»/
  «взлёт закрыт»). Сеть баз становится аэропортовой схемой: одна база — вылеты,
  другая — приём (пропускная способность полосы общая: нативный
  `IsAvailableForTakeoff` держит вылет, пока идёт посадка).
- **Панель аэродрома открывается тремя способами** (v0.102): клик по зданию-невышке
  (нативные аэропорты), клик по РОМБУ аэродрома на карте, клик по ПОЛОТНУ полосы —
  у построенной ВПП вышки нет и не будет, её «представители» — ромб и полотно.
  Тумблеры продублированы при выделении ангара (действуют на его `parentAirbase`;
  только если все выделенные ангары одной базы).
- **Авианосцы/LHA — тоже аэродромы (v0.103)**: `Airbase` — компонент корпуса
  (`Ship.GetAirbase()`), полосы/вертикальные точки едут вместе с кораблём, ромб
  летит над ним. У палубы нет ни вышки, ни ангаров-зданий — тумблеры открываются
  выделением самого корабля (панель «Производство»); enforcement тот же
  (финишированные полосы/трамплины — нативные флаги, вертолётные точки — патч).
  Закрыл посадку на авианосце — его борта уходят на береговые базы.
- **Гранулярность — аэродром** (все полосы базы разом): построенная ВПП = один
  аэродром с одной полосой, у нативных аэропортов с несколькими полосами тумблер
  действует на все.
- **Enforcement — нативные флаги полос** `Airbase.Runway.Landing/Takeoff`
  (write-through из `AirbaseAccess`): поиск ближайшего аэродрома, выдача полосы на
  посадку и руление на взлёт уважают их сами. Вертолётные вертикальные точки флагов
  не имеют — закрытие посадки глушится патчем для них (ARCHITECTURE §6.9).
- **Взлёт закрывается только самолётам** (решение игрока): вертолёты/тилтвинги
  взлетают вертикально и ВПП не занимают. Приказ стоящему самолёту на закрытой базе
  удерживается (Notice), борт ждёт в паркинге и вылетает сам, когда базу откроют
  (взлёт-вахта `SortieService`). Производство и выкат из резерва НЕ гейтятся:
  борта выкатываются и паркуются на апроне — «флот, готовый к вылету».
- **Закрытие последней посадочной базы фракции разрешено** (решение игрока), но
  предупреждается Notice'ом: без посадочной базы нативная игра катапультирует борта
  с малым топливом.
- **До первого тумблера база живёт ровно ванилью** (нативные флаги полос не
  трогаются: у авианосцев полоса может быть только взлётной — трамплин). Флаги —
  фракция-агностичное состояние полосы: захватил враг — его борта тоже
  подчиняются. Тумблеры сбрасываются сменой сцены и не сериализуются в сейвы
  миссии (долг ARCHITECTURE §12-39).

## 4. Порядок реализации (MVP → далее)

Инженерные принципы (v0.4):
- **Все балансные числа — во внешних JSON-профилях** (цены, доходы мексов, тайминги тиров, drain-рейты): балансировка без пересборки, AI читает те же профили.
- **Стартовый комплект слота** — тоже данные шаблона карты (JSON): командирский борт + стартовый аэродром + инженеры + T1-фабрика + стартовые запасы; точный состав настраивается шаблоном под роль слота.

1. **Каркас** BepInEx-плагина + собственное состояние камеры (`CameraBaseState`, без патчей; зум-к-курсору, инерция, стратегический зум).
2. **Выделение + приказы** наземке (`UnitCommand.SetDestination` / серверный вариант).
3. **Экономика v1:** месторождения + поток (упрощённо: доход с мекса, хранилище).
4. **Покупка юнитов** через депо за деньги (паттерн GC).
5. **Стройка:** инженеры + `BuildTask` API (общий для игрока/AI/сети/сейвов).
6. **AI-командир v1:** доктрины поверх того же Task-API.
7. **Авиация:** руление по модели AircraftWaypoints (destination + игровой AutoAim), аэродромы-здания, полосы.
8. **Командирский борт:** юнит, радиус связи, EMCON, победа через его смерть.
9. **Генератор карт** (оффлайн AssetBundle, шаблоны Dual Gap/Setons).
10. Салваж, тиры экономики, эскалация по ущербу, «командир + асы» MP, эксперименталы.

## 6. Риски

- **Early Access churn (0.34.x):** каждый патч игры ломает хуки → пин версии + SelfCheck'и при старте (паттерн GC).
- **Производительность:** цель — сотни юнитов через AI-LOD, троттлинг сети/сканов, летальность вместо спама. GC-потолок 300/сторона с троттлингом.
- **Конфликты модов:** один владелец руления на борт (детект и предупреждение).
- **Лицензии:** NOCommander = Unlicense (можно); AircraftWaypoints — проверить до копирования; бета GC 0.9.9.4 — только референс, код не копировать.
