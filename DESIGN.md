# Supreme Nuclear — дизайн-документ

**Версия:** 0.4 (фабрики с очередями, поведение вне связи, парковка явным списком) · **Дата:** 2026-10-24
**Проект:** RTS-мод для Nuclear Option в духе Supreme Commander.
**Статус:** решения зафиксированы по итогам разведки (см. Реестр технических референсов в конце).

---

## 1. Видение

Оперативная RTS на больших (100×100+ км) симметричных картах с реалистичным вооружением Nuclear Option (BVR-ракеты, мощная ПВО, артиллерия) + уникальный гибрид: командир может лично летать. Темп — оперативный реализм, без ускорения времени. Драки длятся долго — это норма и часть геймплея.

Уникальность против SupCom:
- реальная аэродинамика и вооружение вместо «самолётов на 100 м»;
- личное участие: вселение в любой свой борт;
- 100×100 км против 20×20 у «больших» карт SupCom.

## 2. Зафиксированные решения

### 2.1 Командир = командирский борт игрока («летающий ACU»)
- Интерфейс командования — стратегический слой (оверлей + карта), **не** привязан к кабине.
- Борт — это: (а) юнит-условие победы, (б) узел связи (приказы в радиусе / через ретрансляторы), (в) опциональное личное средство: вселение в кабину в любой момент; без игрока летит сам (маршрут/орбита).
- **EMCON (радиомолчание):** борт глушит РЛС и связь — невидим для пеленга, но слеп и не командует. Симметричный риск.
- **Смерть командира = детонация БЧ** (нативные тактические/стратегические боеголовки) + конец матча.
- Посадка на свой аэродром = ремонт и окно уязвимости.

### 2.2 Экономика (v0.2, детализировано)

**Два ресурса, потоковая семантика (инвариант SupCom #1):**
- **Промресурс («масса»)** — добывается месторождениями (аналог мексов). Апгрейд T1→T2→T3 на самом здании.
- **Энергия** — генераторы (T1/T2/…). Потребляют: заводы (производство юнитов), радары, ПВО, стройка, апгрейды.
- Дефицит = пропорциональное замедление (производство/стройка едут со скоростью min(1, доступно/требуется)); перелив = копится в хранилище. Экранная панель «доход/расход/баланс» — обязательный элемент UI.
- Технически: поток считается mod-side; там, где игра требует `factionFunds`, — периодическая синхронизация эквивалентом (цены всё равно переписываем через `UnitDefinition.value`).
- Позже (не MVP): **топливо/боеприпасы как физическая логистика** — энергия+масса конвертируются в топливо/БО на базах, дальше грузовиками/вертолётами снабжения до аэродромов (паттерн GC supply proven). Это третий слой, дающий оперативную глубину, но не блокирует ядро.

**Экспансионный доход (инвариант SupCom #2):**
- Месторождения фиксированы генератором карт: чокпоинты, центр (жирные). Отдельный тип — **энергетические споты** (аналог гидрокарбонатных): дешёвая станция только на месте спота, ~×5 к эффективности обычного генератора; бонус, а не требование.
- Стартовый набор ресурсов слота = слайдер темпа матча (меньше стартовых мексов/запасов → медленнее и «армейнее» игра — подтверждено наблюдениями по SupCom).
- **Салваж обломков** — возврат массы с полей боёв (нативные wrecks; инженер подъезжает — собирает).

**Автономные командные машины (аналог SACU/«студентов»):**
- Тяжёлый дорогой юнит T3-стадии: инженер-боец. Пассивно **генерит массу+энергию** (как командирский борт), **строит T3-здания** (и эксперименталы, когда появятся), ассистит стройки.
- Пресеты при постройке (бой/инженерия/ресурс — как пресеты SACU).
- Синергия с принципом «стройка где угодно»: одиночная АКМ может тайно строить передовую базу в тылу врага.

**Принцип «без жёстких ролей»:** роли (авиация/наземка/флот/экономика) диктуются только стартовой позицией и стартовыми ресурсами слота. Любой игрок, выйдя в безопасное плато развития, может построить любую ветвь победы. Никаких залочек «этот слот не может строить флот».

**Тайминги (целевые, для среднего игрока; числа — плейсхолдеры до полигона):**

| Стадия | Цель (1v1 / 4v4) | Аналог SupCom |
|---|---|---|
| Первые стычки | 3–5 мин | T1 агрессия |
| T2 (MBT, дальняя ПВО, вертолёты, артиллерия) | 8–10 мин | T2 ~8 мин |
| T3 (стелс-бомберы, флот, тяжёлый танковый кулак) | 15–18 мин (растянуть из-за времени полёта) | T3 ~10 мин на Dual Gap |
| Первая стратегическая БЧ | 20–25 мин (при чистой экономике — 18) | нуклы ~15 мин у экономиста 1500 |
| Противоракетная готовность | к моменту первой БЧ у врага | ПРО к 15 мин |

Крутилки темпа: стартовые запасы, доход мексов по тирам, стоимость апгрейда T2/T3, скорость стройки БЧ-завода, порог эскалации по ущербу.

**Роли слотов на шаблонах карт (аналог позиций Dual Gap):**
- **Аэродромный слот** — усиленный стартовый аэродром + авиационные резервы, меньше мексов (покупает эффект дороже, но летает чаще).
- **Наземные слоты (1–2)** — больше мексов, вариативные расходы: тактические ракеты, мобильные РСЗО, стационарная артиллерия, ПВО-бункеры на линии соприкосновения, танковые массы.
- **Тыловой-экономист** — максимум мексов в тылу, отвечает за T3 и противоядерную защиту команды.
- **Морская позиция** (шаблоны типа Setons) — флот: нативно влиятелен (HP, мультиролевые башни: ПВО + противолодочные + дальнобойные), T2-стадия растянута, корабли = квази-эксперименталы по весу.
- Асимметрия стартовых ресурсов между слотами задаётся шаблоном карты (как в SupCom), а не фракцией.

**Стройка и «вливание» (инженер-ассист — как в SupCom):**
- Любая задача (юнит/здание/апгрейд/БЧ) — это `BuildTask` с полем `drainRate`; несколько инженеров на одной задаче суммируют свой `assistRate` → стройка едет быстрее, но вычитает больше потока. Это и есть «вливание массы/энергии через инженеров и само здание».

### 2.3 Строительство
- **Стройка где угодно** (инженеры, как в SupCom), БЕЗ радиуса базы (анти-паттерн C&C из Ground Control — отвергнут).
- Секретные передовые базы в тылу врага — поддерживаемая фича (следствие: разведка имеет ценность, скрытность строительства — механика).
- Аэродромы — обычные здания (логистика: ёмкость авиации, реарм/ремонт, взлётные полосы), не «владение территорией». Строятся/захватываются как любые структуры.
- **Архитектурный принцип:** вся стройка — API сериализуемых задач (`BuildTask` и др.), общий для UI игрока, AI-командира, мультиплеера и сейвов. AI не может «не уметь строить».

### 2.3-1 Механика стройки SupCom (целевая модель, объяснена игроком 2026-10-26)

- **Инженерный модуль** — «апгрейд», который у инженера выдаётся при создании: им он
  **вливает** ресурсы в стройку (не «строит время», а прокачивает массу/энергию).
- **Shift+ЛКМ** расставляет очередь точек постройки — инженер итеративно использует их
  как вейпоинты: подъехал → залил до конца → поехал к следующей.
- **Несколько инженеров** на одной задаче вливают пропорционально больше — стройка быстрее.
- **Тир инженера** расширяет список доступных к постройке объектов; у каждого инженера есть
  **фактор строй-мощности** (у командира SupCom по умолчанию 10): инженерный модуль повышает
  и тир, и фактор; фактор определяет скорость вливания ресурсов (по формуле экономики).
- Реализовано в v1 (0.35.1): shift-серия площадок, цепочка задач как вейпоинты,
  пропорциональное ускорение от N инженеров (у всех фактор 1). Тиры/фактор/модули —
  вместе с модовыми определениями инженеров и потоковой экономикой (2.2, этап B+).
- **НЕДОСТРОЙ (v0.44.0, философия игрока)**: сорванная инженером стройка НЕ отменяется
  и БЕЗ возврата денег остаётся площадкой с уплаченным прогрессом — её подхватывают
  другие инженеры (ПКМ/shift+ПКМ по недострою выделенными инженерами = достройка).
  Сценарий: T3 инженер ставит дорогие здания и срывается; пачка T1/T2 прокликивает
  недострои и достраивает. Полное удаление площадки — только кликом по плитке очереди.
- **Приказы = вейпоинты намерения (v0.44.0)**: у КАЖДОЙ единицы своя очередь
  (движение/стройка/взлёт/посадка/атака — одна цепочка на юнита); shift+ПКМ дописывает
  в очередь КАЖДОМУ выделенному свою точку; добавление юнита в группу посреди
  прокликивания — последующие вейпоинты получают только текущие выделенные.
  **Shift = режим добавления** вообще: дописывание в очередь И добавление в группу
  (shift+клик по юниту / shift+рамка).

### 2.3a Производство: фабрики с очередями (дефолт v0.4)
- Покупки «по клику за деньги» (паттерн GC-депо) — только костыль для самого первого вертикального среза. Целевая модель — **фабрики с очередями**: заказы стоят в очереди, фабрика непрерывно наливает массу+энергию (`drainRate`), юнит выходит по мере «наполнения». Дефицит потока = пропорциональное замедление всех очередей.
- Приоритеты очереди и точка сбора (rally point) — обязательны. Инженер-ассист ускоряет и производство (суммарный `assistRate`).
- Тиры: апгрейд фабрики на месте (T1→T2→T3) или постройка новой — обе опции, дефолт — апгрейд на месте.
- Авиация производится на аэродромах (ёмкость ангаров ограничивает очередь), флот — на верфи (naval dock, паттерн GC).
- **Источник спавна авиации — ТОЛЬКО родные аэродромы игры** (`Airbase.TrySpawnAircraft`/ангары): их ВПП/такси/посадка работают штатно. Самодельные ангары-спавнеры (как у GC) не используем — по опыту беты ставятся криво и сломаны. Передовые площадки для VTOL — позже через нативный `SpawnCustomAirbase` с VerticalLandingPoints (v0.9 разведка это подтвердила).

### 2.3b Поведение вне радиуса связи (дефолт v0.4)
- Юнит, потерявший связь (вышел из радиуса командира/ретрансляторов), **доигрывает текущий приказ**, затем переходит в автономную оборону (держит позицию, отвечает огнём).
- Циклические приказы (патруль/маршрут) продолжают выполняться до последнего.
- UI обязан явно показывать «нет связи» на юните/группе.

### 2.4 Карты
- **Большие симметричные сгенерированные** карты. Требования: ≥50% манёвренных равнин (танковые бои, контрудары), горы по краям и редкими хребтами (авиационная игра), чокпоинты (река/ущелья), центральные богатые месторождения.
- Шаблоны: Dual Gap (базы + сухопутный мост), Seton's Clutch (континенты вокруг центрального моря), зеркальная симметрия — генерируем половину, отражаем.
- **Две культуры карт — обе в пуле:** (а) фиксированные шаблоны/сид для соревновательных быстрых билдов («знатоки одной карты») и (б) рандом-генерация с хаотично раскиданными мексами и медленными стартами (супер-адаптивные игроки). Генератор один, различается раскадровка депозитов.
- Путь: оффлайн-генератор AssetBundle (пайплайн NOMapLoader доказан Swiss Alps) → позже рантайм-генерация (все примитивы подтверждены: меши, traversability-текстура, RoadNetwork, `SpawnCustomAirbase`).
- Стоковые карты («реальные места», асимметрия) — не для RTS, не используем.

### 2.5 Боевой баланс
- ПВО мощная — норма. Ядро контр-игры — **SEAD-цикл**: разведка → помехи → противорадиолокационные ракеты → удар. Артиллерия бьёт статику (area-fire по точке карты — доказано GC).
- Треугольник: авиация ↔ ПВО ↔ артиллерия/наземка. Точная математика — открытый вопрос.
- Авиация — инструмент разведки/удара, не DPS-бол (BVR вместо dogfight-бол).

### 2.6 Стратегические БЧ: органический баланс вместо гейтов (v0.3)
**Отказ от «эскалации по ущербу» как разрешения** — механика хороша для ванильного Nuclear Option, но в RTS-режиме заменяется органической контригрой в духе SupCom:
- **БЧ-завод строится где угодно** (никаких уникальных месторождений — иначе перманентный снос добытчика превращает стратегическое оружие в мёртвую механику). Дорогой, энергожоркий, **заметный на разведке** (крупная сигнатура: раз увиден — виден всем).
- **ПРО строится быстрее и дешевле первой БЧ** — как в SupCom: засёк ядерное ядро → ушёл в экономику/ПРО и успел. Цикл «разведка → реакция» заменяет разрешающую систему.
- **Риск раннего выхода** — плато уязвимости: пока строишь БЧ-завод, армия тоньше; противник это видит (мало техники на разведке) и наказывает штурмовиками/танковым рейдом. Самобаланс через разведку, не через скрипт.
- Нативные гейты эскалации в нашем режиме **отключаются** (патчи `MissionManager.AllowTactical/AllowStrategic` — цели уже доказаны GC). Нативная эскалация остаётся для ванильных режимов игры.
- Производство = потоковая стройка с инженер-ассистом (`BuildTask.drainRate`), наполняет **нативный** warhead stockpile (`FactionHQ.AddWarheadStockpile`) — носители, пусковые и применение берутся из игры бесплатно.
- Тактические БЧ — та же система, дешевле/быстрее, меньший масштаб.
- Урановые месторождения **исключены из v1** (возможный возврат позже — как опциональный ускоритель БЧ-завода ×1.5, не как требование).

### 2.7 Победа
- **Гибрид:** дуэль командиров (убей борт) + система objectives (нативная) для PvE-миссий; задел на кампанию.

### 2.8 Мультиплеер
- Режим **«командир + асы»** (один командует, остальные летают его бортами) — да, целевой. Не MVP.
- **Респаун асов (дефолт v0.4):** летающие игроки возрождаются на аэродроме своей фракции (нативно), смерть командира = конец матча. Ас, чей борт сбили, возвращается на следующем свободном борта из резерва.
- **Передача ресурсов союзникам (дефолт v0.4):** отправка массы/энергии союзнику кнопкой (для командной игры «фид экономиста»). Передача юнитов — паркинг.
- MVP-сингл: игрок против AI-командира.

### 2.9 Парковка (явный список отложенного)
- **Эксперименталы** — возможно модовые юниты позже.
- **Энергощиты** (ты про Т2-щиты в бункерах) — технически возможны (патч `UnitPart.TakeDamage` доказан GC), но новая механика; решение после первых полигональных стычек с ПВО.
- **Масс-фабрикаторы** (конвертация энергия→масса поздней игры) — нужен только если карты упираются в исчерпание мексов; ввести при необходимости.
- **Погода/время суток как геймплей** (ночные операции, влияние ветра на авиацию) — нативная среда игры это умеет; геймплейное использование — после ядра.
- **Передача юнитов союзникам, зрители, рейтинг** — MP-инфраструктура, далеко.

### 2.10 Нижняя панель командования — эталон SupCom FA (спека от 2026-10-26, со скриншотов игрока)

Эталон для нашей нижней панели. Записан до реализации; дорабатывается под NO.
Реализация — этап B (вместе с Task-API/фабриками). Раскладка панелей экрана — ARCHITECTURE §8.

**Три вкладки** (иконки, вертикальный селектор сбоку):
1. **Гаечный ключ — стройка/производство.**
   - Две строки. **Верхняя — строка заказа**, визуально подразделена: «апгрейд на тир выше» / «юниты».
   - Над ней 5 иконок переключения пула заказа: **тиры I, II, III, экспериментальные (круг), шаблоны (2 квадрата)**.
     Кнопки тира показывают в строке заказа юниты выбранного тира.
   - **Шаблоны**: запомнить текущую очередь кнопкой «шаблон» сбоку; применение шаблона заказывает
     пачку юнитов без ручного набора (автоматизация). Шаблоны работают и для постройки зданий,
     не только очередей юнитов.
   - Кнопки у строк: **«цикл»** (зацикливание очереди — бесконечное производство) и
     **«пауза/воспроизведение»** производства. Активное состояние — яркая подсветка.
   - По **8 кнопок прокрутки на строку**: листать иконки влево/вправо по одной и до конца в обе стороны.
2. **Список юнитов.**
   - **Верхняя строка — выделенные объекты** (в SupCom: shift+клик или обводка; здания НЕ обводятся
     рамкой, чтобы не мешали — добавляются в выделение только прокликиванием, накапливаясь в строке).
   - Элементы строки разделены **визуальными промежутками по категориям**: юниты / инженеры
     (занятые и свободные отдельно) / боевые / здания / функциональные объекты / заводы.
   - **Нижняя строка — строка заказа инженеров**, если в выделение попали заводы.
   - При **множественном выборе заводов** очереди в нижней строке НЕ показываются
     (в каждом заводе может быть своя очередь).
3. **Апгрейды командира и SACU** — для NO пока не актуальна (задел под командирский борт/АКМ).

**Адаптация под NO (открытые пункты к этапу B):**
- Вместо двух ресурсов mass/energy — пока деньги (`factionFunds`); панель потока — этап C.
- Авиация производится на аэродромах (ёмкость ангаров вместо слотов очереди).
- «Экспериментальные» — пусто до появления эксперименталов (паркинг-лист 2.9).
- Шаблоны v1 — именованные наборы заказов; сохранение между матчами — после сейвов.
- Прокрутка строк и «цикл/пауза» переносятся как есть; «цикл» требует фабрик с очередями (Task-API).
- **Шаблоны = отдельная вкладка «Ш»** (реализовано v0.42.0): верхняя строка — сохранённые
  наборы (иконка-представитель = самое дорогое в наборе); нижняя — текущий контекст
  (очередь фабрики/инженера или НАБОР выделенных зданий). Сохранение «Шаблон+»:
  очередь фабрики (позиции, как раньше) или набор построек с ОТНОСИТЕЛЬНЫМИ позициями
  (shift+клик накапливает здания в группу; ПКМ по плитке набора убирает лишнее).
  Применение: фабрика — клик по шаблону добавляет весь набор в конец очереди (миксы);
  инженер — призраки всех построек у курсора с сохранёнными смещениями; заблокированные
  точки (вода/склон/занятая зона) подсвечены красным и при постановке ПРОПУСКАЮТСЯ;
  Shift — серия (достраивание соседних участков).
- **Открытый вопрос №9: невидимая сетка SupCom** — в SupCom здания снапятся к сетке,
  что делает shift-прокликивание гигантских grids набором шаблонов силами нескольких
  групп инженеров. Адаптировать ли сетку для NO (и в каком размере клетки) — подумать;
  v0.42.0 не использует сетку, смещения свободные.

## 4. Порядок реализации (MVP → далее)

Инженерные принципы (v0.4):
- **Все балансные числа — во внешних JSON-профилях** (цены, доходы мексов, тайминги тиров, drain-рейты): балансировка без пересборки, AI читает те же профили.
- **Стартовый комплект слота** — тоже данные шаблона карты (JSON): командирский борт + стартовый аэродром + инженеры + T1-фабрика + стартовые запасы; точный состав настраивается шаблоном под роль слота.

1. **Каркас** BepInEx-плагина + собственное состояние камеры (`CameraBaseState`, без патчей; зум-к-курсору, инерция, стратегический зум).
2. **Выделение + приказы** наземке (`UnitCommand.SetDestination` / серверный вариант).
3. **Экономика v1:** месторождения + поток (упрощённо: доход с мекса, хранилище).
4. **Покупка юнитов** через депо за деньги (паттерн GC).
5. **Стройка:** инженеры + `BuildTask` API (общий для игрока/AI/сети/сейвов).
6. **AI-командир v1:** доктрины поверх того же Task-API.
7. **Авиация:** руление по модели AircraftWaypoints (destination + игровой AutoAim), аэродромы-здания, полосы.
8. **Командирский борт:** юнит, радиус связи, EMCON, победа через его смерть.
9. **Генератор карт** (оффлайн AssetBundle, шаблоны Dual Gap/Setons).
10. Салваж, тиры экономики, эскалация по ущербу, «командир + асы» MP, эксперименталы.

## 6. Риски

- **Early Access churn (0.34.x):** каждый патч игры ломает хуки → пин версии + SelfCheck'и при старте (паттерн GC).
- **Производительность:** цель — сотни юнитов через AI-LOD, троттлинг сети/сканов, летальность вместо спама. GC-потолок 300/сторона с троттлингом.
- **Конфликты модов:** один владелец руления на борт (детект и предупреждение).
- **Лицензии:** NOCommander = Unlicense (можно); AircraftWaypoints — проверить до копирования; бета GC 0.9.9.4 — только референс, код не копировать.
